# 海关归类助手（PoC）

一句话：你说一句大白话描述商品，它回你一个可申报的 HS 编码，带依据、带税费，还会告诉你哪儿不确定。

> 不懂代码也能看：往下读「30 秒看懂」和「它到底替你做了什么」两节就够了。
> 技术细节在「背后的东西」之后，可以跳过。

---

## 30 秒看懂

你说的：

> 客户从越南进口一批塑料颗粒，说是聚乙烯，比重 0.92 左右

它回的：

| 项目 | 内容 |
|---|---|
| 编码 | 3901.1000 初级形状的乙烯聚合物：聚乙烯，比重小于 0.94 |
| 依据 | 引自《2026 年进出口税则》第 509 页原文，不是它自己编的 |
| 税费 | 按 1 万元完税价算：关税 0 + 增值税 1300 = 合计 1300 元（综合 13%） |
| 为什么不选别的 | 3901.2000 要求比重 ≥ 0.94，0.92 不够；3901.4020 是 LLDPE，密度同样落在这个区间，光看数字排除不了 |
| 置信度 | 中 —— 因为「0.92 左右」可能正好跨过 0.94 这条线 |
| 你要补什么 | 是均聚还是共聚？比重实测值到底多少？测试标准是什么？ |

最后一栏是关键：它没有硬给你一个「大概是」。

## 它到底替你做了什么

报关归类这件事，难的从来不是「查得到」，是这三件：

1. 翻不完 —— 2026 版税则有 8972 条编码，人不可能都记住。它来查。
2. 说不清依据 —— 归错编码是要担责任的，你得指得出税则原文。它的每个编码都能追回到工具返回的原文片段。
3. 把不确定藏起来 —— 这是最危险的。很多工具会硬给一个答案，你不知道它有多心虚。这套东西会主动写「置信度：中/低」和「你还需要确认什么」。

第 3 点是这个 PoC 真正想验证的东西。

## 为什么它比「直接问 AI」靠谱

| | 直接问聊天 AI | 这个 PoC |
|---|---|---|
| 编码从哪来 | 模型凭记忆编，你没法核 | 只从税则库查，查不到就说查不到 |
| 会不会编 | 会，而且编得很像真的 | 角色里写死了「不许自己编编码」 |
| 依据 | 「根据海关规定」——没有具体出处 | 引用税则原文 + 页码 |
| 拿不准时 | 照样给你一个肯定的答案 | 标置信度，列缺什么 |

## 实测结果（5 个真实商品，全部来自真实工具调用）

| 商品 | 结论编码 | 置信度 | 它主动发现的问题 |
|---|---|---|---|
| 聚乙烯颗粒（比重 0.92） | 3901.1000 | 中 | LLDPE（3901.4020）无法仅凭密度排除；名称含「6.5」与工具税率 `0.0%` 互相矛盾，它拒绝拍板 |
| 烘焙面包 | 1905.9000 | 中 | 缺形态/配方，无法在 1905.90 与 1905.40 之间自定 |
| 香水 | 3303.0000 | 编码高 / 税费低 | 主动指出消费税 0% 与「高档化妆品」规则冲突 |
| 去壳腰果 | 0801.3200 | 高 | 限定前提（生/干、仅机械去壳），熟制调味则不成立 |
| 葡萄糖粉 | 1702.3000 | 中 | 缺果糖含量，无法确认 1702.30 / 1702.40 分界 |

5 个里只有 1 个给「高」 —— 这个克制就是它可信的地方。

它还做到了一件容易错的事：搜「聚乙烯」时把 3905.3000（聚乙烯醇 PVA） 和 3920.9100（PVB 薄膜） 正确识别为「同名词、不同物质」剔掉了，没有照着关键词照抄。

## 背后的东西（技术读者看这里）

### 建筑结构

一句话被拆成两道工序，各有独立职责和固定输出格式：

```
用户一句话
   ↓
planner（第一道：只拆解，不许编编码）
   输出 → 商品 / 关键特征 / 可能章 / 需查证 / 风险点
   ↓
checker（第二道：只查证，每个编码必须来自工具返回）
   输出 → 编码 + 引用原文 + 税费 + 候选对比 + 置信度 + 待确认
```

两条硬规矩是这个 PoC 的核心设计：

- planner 不许自己编 HS 编码（查证是 checker 的活）
- checker 的每个编码必须来自工具的返回原文

### 技术栈

| 层 | 用了什么 |
|---|---|
| 代理框架 | OpenClaw 2026.10.7（多代理、隔离 workspace、AGENTS.md 约定） |
| 模型 | DeepSeek `deepseek-flash` |
| 工具层 | MCP（Model Context Protocol）自研 server |
| 工具数 | 3 个：`search_hs_code` / `get_hs_detail` / `calculate_tax` |
| 数据 | 8972 条 2026 版进出口税则 + 1228 条章注 |
| 运行时 | 便携版 Node 24.22.1（隔离安装，不动系统 Node） |

### 这个 PoC 验证了三件事

1. 代理能不能守住边界：planner 被禁止编编码，它确实只做拆解；checker 的每个编码都能回溯到工具返回原文。
2. 会不会主动暴露不确定性：工具返回值有矛盾时它停下来报警（税率 6.5 vs 0.0%），而不是挑一个用。
3. 排干扰项的能力：同名词不同物（聚乙烯醇 vs 聚乙烯）能识别，不是关键词照抄。

## 还没做的（诚实清单）

- 多代理协同目前是「人工串联」（我手动把 planner 的输出交给 checker），
  没有配 `sessions_spawn` 自动委派 —— OpenClaw 支持，但这一版没接
- 只有 3 个 MCP 工具；没有做批量并行（10 条一起跑）
- 没有接监管条件 / 原产地数据，税费只算到关税 + 消费税 + 增值税
- 没有前端界面，交互靠命令行

## 怎么跑

```bash
# 数据目录用环境变量指定（默认读同级 ./data）
export HS_CODE_DATA=/path/to/hs-data

# MCP server 已注册为 hs-code-poc
openclaw mcp probe hs-code-poc

# 第一道：拆解
openclaw agent --local --agent planner --message "客户进口聚乙烯颗粒，比重 0.92"

# 第二道：查证（把上面的任务单粘进来）
openclaw agent --local --agent checker --message "<任务单>"
```

## 文件

| 文件 | 内容 |
|---|---|
| `mcp/hs_code_poc_server.py` | MCP server（3 工具，接 8972 条全量税则） |
| `agents/planner/AGENTS.md` | planner 的角色定义与输出格式 |
| `agents/checker/AGENTS.md` | checker 的角色定义与硬规矩 |
| `evidence/live/*.txt` | 4 次真实运行的原始输出 |
| `evidence/shots/demo_full.png` | 演示全图（一次看完全流程） |
| `evidence/PoC演示.mp4` | 演示视频（19 秒） |

## 演示怎么来的

agent 单次调用 30–60 秒，且多个进程会争抢状态库（实测报 `state database is busy`），
桌面录屏会把「卡住不动」录进去。

所以：先真实跑完把输出存盘（`evidence/live/`），再用无头浏览器渲染成终端风格页面，
逐帧截图合成视频。视频与截图里每一行都是真实运行结果，未改写；页面上也明确标注了
「本段为真实运行的实录回放」。
